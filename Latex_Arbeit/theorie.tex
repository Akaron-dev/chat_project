\chapter{Die Client-Server-Struktur}

Als erstes, wollen wir verstehen, wie ein Messaging-Programm grundsätzlich funktioniert. Unser Ziel ist es, von einem Gerät A eine Nachricht an ein anderes Gerät B versenden zu können. Dies sollte möglichst wenig Leistung gebraucht werden, möglichst schnell stattfinden, und die Nachricht darf für Niemanden ausser dem Absender und den Empfänger lesbar sein. Um dies zu tun, gibt es schon sehr viele Programme. Die meisten können jedoch anhand ihres Funktionsprinzips in drei Unterkategorien eingeteilt werden. Diese sind die Client-Server-Struktur, das Peer-to-Peer-Messaging und das föderierte Servermodell.
\section{Das Funktionsprinzip der Client-Server-Struktur}
Die Client-Server-Struktur ist das verbreitetste Modell für Messaging-Programme und auch dasjenige, welches wir für unser Projekt benutzen. In diesem Modell werden Clients benutzt, die sich alle mit einem Server verbinden\footnote{Dies kann auch einen Server Cluster sein}.
 Der Client ist ein Programm, das auf dem Gerät jedes Nutzers läuft. Der Client dient dazu, Nachrichten an den Server zu senden und sie von ihm zu empfangen. Dazu hat er ein Interface, auf dem die Nachrichten angezeigt werden und neue verfasst werden können. Der Server ist eine zentrale Rechenmaschine, welche gleichzeitig mit allen Clients verbunden ist. Er speichert die vom Client verschickten Nachrichten ab, bis er eine Verbindung zum gewählten Empfänger erstellt hat und leitet sie dann an ihn weiter. Zusätzlich kann dieser, wenn er die Nachricht empfängt und liest, dies dem Server mitteilen, und dieser leitet dies an den Sender zurück. Bekannte Beispiele für Programme, die diese Struktur verwenden, sind WhatsApp und Signal. Einige Programme, wie zum Beispiel Discord, löschen die Nachrichten nicht vom Server, nachdem sie weitergeleitet wurden. Dies ermöglicht dem Nutzer, alle vergangenen Nachrichten auf einem neuen Gerät abzurufen.

\subsection{Kryptologie}
Wenn ein Messaging-Programm Nachrichten direkt verschickt, erlaubt das allen, sie auch zu lesen, solange man Zugriff auf das Netzwerk der beteiligten Clients oder des Servers hat. Dies ermöglicht keine Privatsphäre. Um das zu verhindern, benutzt man ein Verfahren namens Verschlüsselung.
\\\\
Die Definition von Wikipedia: 
\begin{quote}
	\textit{"Verschlüsselung nennt man die Umwandlung von Informationen, genannt Klartext, in einen Geheimtext.
     Dies geschieht mithilfe von kryptografischen Verfahren unter Verwendung eines geheimzuhaltenden Schlüssels,
     der nur den befugten Personen bekannt sein darf. Mit Kenntnis des Schlüssels kann der Geheimtext wieder in den Klartext zurückgewandelt werden,
     was Entschlüsselung genannt wird."
}
\end{quote}
Um in einem Messaging-Programm Privatsphäre garantieren zu können, benötigt man eine Ende-zu-Ende-Verschlüsselung. Das bedeutet, dass die Nachricht am Ende des Absenders verschlüsselt wird und nur am anderen Ende, dem des Empfängers, entschlüsselt werden kann. Niemand dazwischen darf die Nachricht entschlüsseln können. Der Server erhält also nur eine verschlüsselte Version Nachricht. Um die verschlüsselte Nachricht wieder zu entschlüsseln, braucht der Empfänger jedoch zwingend den Schlüssel. Dies ist jedoch bei einer symmetrischen Verschlüsselung, eine Verschlüsselung bei der der gleiche Schlüssel zur Entschlüsselung wie zur Verschlüsselung verwendet wird, ein Problem. Da der Empfänger den Schlüssel haben muss, um die Nachricht zu entschlüsseln, müsste der Schlüssel auch mitgeteilt werden. Dabei hätte aber jeder Zugriff auf den Schlüssel und die verschlüsselte Nachricht und könnte sie somit selbst entschlüsseln. Um dieses Problem zu, lösen benutzt man eine asymmetrische Verschlüsselung.

\subsubsection{Die asymmetrische Verschlüsselung}
Die asymmetrische Verschlüsselung zeichnet sich dadurch aus, dass sie nicht den gleichen Schlüssel zur Verschlüsselung und Entschlüsselung verwendet. Um dies zu erreichen, gibt es verschiedene Algorithmen, die alle dem gleichen Prinzip folgen. Bei der Erstellung eines Accounts generiert der Client A ein sogenanntes Key-Pair. Dieses besteht aus einem Public und einem Private Key. Der Public Key wird offen an alle anderen Nutzer versendet, der Private Key wird lediglich auf dem Gerät des Nutzers A gespeichert. Wenn Client B eine Nachricht an Client A versenden möchte, benutzt er den Public Key von Client A, um diese zu verschlüsseln. Dieser kann aber nicht verwendet werden, um die Nachricht wieder zu entschlüsseln. Nur mit dem Private Key von Client A ist es möglich, die Nachricht wieder zu entschlüsseln. So wird eine sichere Kommunikation ermöglicht, ohne die Schwachstelle, dass ein Schlüssel zur Entschlüsselung ausgetauscht werden muss. Solange alle Private Keys geheim bleiben, ist die Privatsphäre garantiert. Der Nachteil an diesem Verfahren ist, dass die Algorithmen für die asmmyetrische Verschlüsselung viel langsamer sind und mehr Rechenleistung brauchen.
\subsubsection{Das Hybrid-Kryptosystem}
Als letzte art der verschlüsselung werden wir das hybrid kryptosystem anschauen. Sie ist wie der name schon Andeutet eine verbindung aus der asymmetrischen und symmetischen Verschlüsselung. wenn Client A eine nachticht versendet wird zuerst ein zufälleriger session-key genereirt. Dieser wird dann benutzt um die nachricht, die grosse datenmenge, effizient symetrisch zu verschlüsseln. Danach wird der session-key asymetrisch verschlüsselt mit dem Public-Key von Client B. da der session key sehr klein ist wird trots asymetrischer verschlüsselung wenig zeit und rechenleistung verbraucht. Danach werden die Verschlüsselte nachticht und der Verschlüsselte Session key an Client B versendet. Dieser entschlüsselt zuerst den Session kex mit seinem Provate key und kann dann die nachricht mit dem session key symetrisch entschlüsseln. Bei diesem vorgang wird die grosse datenmenge effizient verschlüsselt mit der symetrischen verschlüsselung und ist trotzdem sicher da der session key asymetrisch verschlüsselt wird.
